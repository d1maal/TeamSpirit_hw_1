# Task1
## Данные и разбиение

Всего есть 3000 размеченных диалогов.
Для разработки использовали:
- 2400 диалогов - train;
- 600 диалогов - отдельная итоговая проверка.
На train классы распределены примерно так:

| Класс | Доля |
|---|---:|
| neutral | 59.1% |
| negative | 30.8% |
| positive | 10.1% |
Что было весьма грустно.
Из-за редкого `positive` при обучении использовали балансировку классов.

В данных также есть несколько очень похожих диалогов. Поэтому при кросс-валидации использовалось групповое разбиение. То есть похожие диалоги и все реплики одного диалога всегда остаются в одной части разбиения. Мы подумали, что это уменьшит риск утечки между train и validation.

Подбор моделей и параметров делался только по кросс-валидации на 2400 train-диалогах. Отложенные 600 диалогов использовались для итоговой проверки уже выбранных моделей.

## Базовые модели

Сначала нами задача решалась как обычная классификация полного текста диалога по TF-IDF.
Проверялись три базовые модели:

| Модель | Macro-F1 |
|---|---:|
| Naive Bayes | 0.5408 |
| Logistic Regression | 0.6093 |
| SVM | 0.6061 |

Простые модели дали разумный baseline, но особенно плохо работали с редким классом positive.

## Главное из того, что мы заметили по разметке

В датасете есть разметка реакции не только для целого диалога, но и для отдельных пользовательских реплик.
Мы проверили диалоги и заметили правило:

Итоговая реакция диалога равна последней ненейтральной реакции пользователя; если ненейтральных реакций нет, итоговая реакция neutral. Ну и попытались применить это знание при обучении, не используя напрямую
Поэтому дальше задача была разбита на два шага:
1. предсказать реакцию каждой пользовательской реплики;
2. применить правило последней ненейтральной реакции уже к предсказаниям модели.

## Своя гипотеза: важен контекст вокруг пользовательской реплики

Мы предположили, что реакцию пользователя лучше определять не только по его сообщению, но и по соседним ответам ассистента:

```text
предыдущий assistant -> текущий user -> следующий assistant
```

Например, короткая фраза про добавление деталей может быть обычным продолжением разговора, а может означать, что предыдущий ответ был недостаточно подробным. Следующий ответ ассистента иногда помогает это различить: он может признать ошибку, извиниться, принять уточнение или просто продолжить объяснение.

Для трёх частей взаимодействия использовались отдельные TF-IDF-признаки. Также были добавлены символьные n-граммы и несколько простых структурных признаков.

Для позитивов и негативов обучались отдельные бинарные SVM, после чего применялось правило последней ненейтральной реакции.

### Проверка гипотезы

Мы сделали следующее: по очереди убирали части полной модели и сравнивали результат на одинаковых пяти внешних групповых фолдах.
(Помним, что G=Grigoriy)

| Вариант | Mean CV Macro-F1 | Изменение |
|---|---:|---:|
| Полная модель G | **0.6971** | — |
| Без следующего ответа assistant | 0.6623 | -0.0348 |
| Без предыдущего ответа assistant | 0.6859 | -0.0112 |
| Без структурных признаков | 0.6877 | -0.0094 |
| Общий TF-IDF вместо раздельных | 0.6804 | -0.0166 |

Самое большое падение получилось при удалении **следующего ответа ассистента**. Причём полная модель была лучше этого варианта на всех пяти фолдах.
То есть таким образом наша гипотеза подтвердилась: контекст вокруг пользовательской реплики действительно помогает классификации.

## Ручные сигналы (а почему бы, собственно, и нет)
После этого добавили несколько простых признаков, которые описывают характер взаимодействия:
- благодарность;
- просьбу исправить ответ;
- признаки ошибки;
- извинение ассистента;
- признаки несоответствия ответа запросу.
(Но на самом деле там их побольше)
Они дали нам дополнительный прирост:

| Модель | Mean CV Macro-F1 |
|---|---:|
| Контроль G | 0.6935 |
| G + ручные сигналы | **0.7124** |

При этом попытка добавить все попарные произведения этих признаков ухудшила результат до 0.6886, поэтому в финальную модель их не включали.

## Decision_2x

После анализа ошибок появилась ещё одна идея: ошибки на разных репликах имеют разную цену.
Если модель ошиблась на ранней реакции, но позже правильно нашла последнюю ненейтральную реакцию, итоговый класс всё равно будет правильным. А если пропустить именно определяющую реплику, итог диалога скорее всего изменится.

Поэтому в  Decision_2x при обучении увеличен вес:
- последней истинной ненейтральной реплики;
- нейтральных реплик после неё;
- реплик полностью нейтральных диалогов.
Для них используется вес 2, для остальных - 1.

Истинные реакции используются только при обучении. На валидации и тесте модель получает только текст диалога.

Чтобы проверить, что эффект не связан просто с другим  class_weight, обе модели сравнивались при одинаковом class_weight="balanced", одинаковых признаках, одинаковых фолдах и одинаковом подборе параметров.

| Модель | Mean CV Macro-F1 |
|---|---:|
| G_signals | 0.7057 |
| **Decision_2x** | **0.7128** |

Как итог, Decision_2x  оказался лучше на всех пяти фолдах контрольного эксперимента.

## То, чего ждали все, но боялись спросить..
**Ура, результаты)))**

На отложенных 600 диалогах:

| Модель | Macro-F1 | Accuracy |
|---|---:|---:|
| **Decision_2x** | **0.7362** | **0.8000** |
| Score-stacking LR | 0.7001 | 0.7417 |

Для Decision_2x основные ошибки:
- `negative -> neutral`: 53;
- `positive -> neutral`: 20;
- `neutral -> negative`: 26.
Recall по классам:
- `neutral`: 0.9014;
- `negative`: 0.6865;
- `positive`: 0.5500.

То есть модель хорошо сохраняет  нейтралы, но часть ненейтральных реакций всё ещё пропускает(

## Разбор полётов

Для ранней версии модели мы ещё отдельно отсмотрели и разобрали ошибки на уровне пользовательских реплик.

На двух сохранённых внешних фолдах было 218 ошибочных итоговых предсказаний:

| Тип ошибки                                   | Число |  Доля |
| -------------------------------------------- | ----: | ----: |
| Пропущена определяющая ненейтральная реплика |   147 | 67.4% |
| Ложная реакция в полностью neutral-диалоге   |    64 | 29.4% |
| Ложная реакция после определяющей            |     4 |  1.8% |
| Неверно определён знак реакции               |     3 |  1.4% |

Главная проблема - не различение `positive` и `negative`, а сам поиск ненейтральной реакции.
При просмотре конкретных примеров оказалось, что граница между `neutral` и `negative` иногда неочевидна. Например, обычное техническое уточнение может выглядеть почти так же, как претензия к ответу. Поэтому простые правила по словам `wrong`, `error`, `fix` и т.п. не решили задачу полностью.

## Что пробовали допом

Мы проверили ещё несколько идей:

| Идея                                          | Что получилось                                          |
| --------------------------------------------- | ------------------------------------------------------- |
| Порог в зависимости от позиции реплики        | почти без изменений                                     |
| TF-IDF + TruncatedSVD                         | прирост около 0.0015                                    |
| FCA (Знаем, что нельзя, но попытаться стоило) | отдельно работал хуже SVM, в комбинации прироста не дал |
| Попарные взаимодействия ручных сигналов       | стало хуже                                              |
| Дополнительный TF-IDF текста без кода и логов | стало хуже                                              |
| Отдельный LR-gate neutral / non-neutral       | заметного улучшения не дал                              |
| Взвешивание примеров по извинениям assistant  | маленький и нестабильный эффект                         |
| Complement Naive Bayes в gate                 | улучшил gate, но не обошёл Decision_2x                  |
| Score-stacking LR                             | хуже Decision_2x                                        |
НО!!!!!
Score-stacking интересен тем, что лучше находит редкие позитивы, но делает слишком много ложных положительных предсказаний. Поэтому основной моделью оставили Decision_2x. Но так как не было ограничения на количество своих моделей, то мы оставили обоих: и агрессора, и консерватора

## Finally...

Лучший результат получился не из-за одного более сложного классификатора, а из-за использования структуры диалога.
Самые полезные идеи:
1. классифицировать отдельные пользовательские реакции, а не только весь диалог;
2. использовать предыдущий и следующий ответы ассистента;
3. векторизовать разные части взаимодействия отдельно;
4. добавить несколько простых ручных сигналов;
5. сильнее учитывать реплики, от которых реально зависит итоговая метка;
6. итоговый класс получать по правилу последней ненейтральной реакции.
Финальная основная модель - **Decision_2x**.
**Mean CV Macro-F1 = 0.7128.**
На отложенных 600 диалогах:
**Macro-F1 = 0.7362, Accuracy = 0.8000!!!!!!!!!!!!!!!!!!!**
